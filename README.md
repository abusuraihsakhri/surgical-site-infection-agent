# Surgical Site Infection Agent

A **synthetic-data threshold demonstration** with Python command-line tools, a FastAPI backend, a browser interface, and automated regression tests. The repository contains three historically separate audit interfaces; their outputs and input schemas are not interchangeable.

**Important:** Despite historical class names, this code **does not implement CDC/NHSN surgical-site infection definitions, 30-/90-day surveillance logic, superficial/deep/organ-space classification, validated risk prediction, or clinical decision support.** Numeric cutoffs (e.g., 25 and 12 in the main API) are arbitrary illustrative rules. Do not use results for patient care, infection reporting, or surveillance statistics.

## Browser application

Open `web/index.html` directly in a modern browser, or serve the application locally through FastAPI. The default **Browser demo** mode runs JavaScript rules entirely on-device, with no server calls and no dependency downloads. It reports true rule-derived alerts rather than fabricated example dossiers; local results are **unsigned**.

**Connected FastAPI backend** mode posts to `./api/audit` on the *same origin* and only works when the page is served by the Python backend. If the backend is unavailable or rejects input, the UI shows an error rather than substituting simulated results. JSON export is available for successful evaluations. The static browser mode is suitable for GitHub Pages; Python APIs, HMAC signing, and telemetry require a server and cannot operate on Pages.

Never enter real names, contact details, medical record numbers, or other identifiable patient information. The backend has limited regex-based identifier checks, **not** comprehensive PHI de-identification or HIPAA certification. Browser mode holds results in memory for the current tab; exports occur only when requested.

## Installation and development

Python 3.10–3.12 are covered by CI (project metadata allows Python 3.9+). Node.js 22 is used only for browser regression tests.

```bash
python -m pip install -e . pytest httpx
python -m pytest -q
node --check web/engine.js
node --check web/app.js
node --test tests/test_web_engine.cjs
```

Start the main API and its built-in web interface:

```bash
python cli.py serve --host 127.0.0.1 --port 8000
```

Then open `http://127.0.0.1:8000/`. The API provides `/health`, `/api/audit`, `/api/chat`, `/api/audit/logs`, `/metrics` (Prometheus text), and autogenerated `/docs` and `/openapi.json`.

## Python workflows

The main API and CLI use `task_id`, `target_identifier`, `primary_metric`, `secondary_metric`, `status_descriptor`, and `is_critical_flag`:

```bash
python cli.py audit --task-id DEMO-001 --target SYNTH-001 --primary 29 --secondary 13
python cli.py verify-audit
python cli.py chat "show configuration"
```

The older package CLI and standalone sentinel use different synthetic input fields and output schemas:

```bash
surgical-site-infection-engine audit --case-id DEMO-001 --primary 29 --secondary 13
surgical-site-infection-engine batch --input sample.csv --output results.csv
python ssi_sentinel.py audit --case-id DEMO-002
python simulator.py 100
```

CSV flags accept `true/false`, `1/0`, and `yes/no` (case-insensitive); invalid values are rejected. The supplied `sample.csv` follows the package CLI schema, *not* the main `cli.py` schema.

## Security and deployment

The main backend records HMAC-SHA256-linked audit **metadata** in volatile process memory. Integrity verification recomputes signatures; the logs and signing key are not persisted automatically. Without `AUDIT_SECRET_KEY`, the backend generates a random key and warns that historical verification will not survive restarts. Production deployment requires a strong, unique secret, access controls, HTTPS, persistent storage, and an independent privacy/security review; the example server does not supply all of these controls.

```bash
export AUDIT_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
docker compose up --build
```

`docker-compose.yml` refuses to start without a configured audit secret. Do not commit keys or real clinical data. The LLM provider factory implements **only a deterministic local mock**; Ollama, Claude, and OpenAI integrations are not implemented.

The `.github/workflows/ci.yml` workflow checks Python builds/tests and the browser rules. `.github/workflows/pages.yml` contains static Pages deployment configuration; Pages must be enabled for the repository's **GitHub Actions** source before deployment can succeed.
